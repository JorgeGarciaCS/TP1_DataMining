# Decisiones de Calidad y Preparación de Datos

Este documento registra las decisiones tomadas en la fase de preparación, cumpliendo con la exigencia de no "inventar" problemas técnicos donde no los hay.

| Problema / Ítem | Detección y Evidencia | Decisión | Justificación | Alternativa Descartada / Riesgo |
| :--- | :--- | :--- | :--- | :--- |
| **1. Valores Faltantes** | `train_df.isna().sum()` muestra 0 nulos técnicos. | No aplicar `SimpleImputer` como paso correctivo inmediato, pero sí incluirlo en el pipeline. | Los autores reportan "Missing Values: No". Incluir el imputer en el pipeline final asegurará robustez en producción frente a nuevos datos. | **Alternativa**: Inventar NAs.<br>**Riesgo**: Falsificar la naturaleza de los datos. |
| **2. Categorías numéricas y Cardinalidad** | Variables nominales (ej. `Nacionality`, `Course`) están como enteros. Alta cardinalidad y categorías raras. | `OneHotEncoder(min_frequency=0.01, handle_unknown='infrequent_if_exist')` para el modelo lineal. Para modelos de árboles, se evaluará usar `OrdinalEncoder` o categóricas nativas. | Agrupar categorías raras previene explosión de dimensionalidad y overfitting en nacionalidades infrecuentes. El encoding debe diferir por modelo. | **Alternativa**: OHE sin `min_frequency`.<br>**Riesgo**: Sobreajuste (overfitting) a un estudiante con una nacionalidad única. |
| **3. Valores Extremos (Notas = 0)** | Cruzando `grade=0` con `evaluations`: Un grupo tiene 0 por ausencia de evaluación, otro rinde y saca 0. | **Conservar los 0s y crear variable `sin_evaluaciones_1s`**. | La tasa de abandono cuando no hay evaluaciones es 68.5%. Cuando sí hay, y sacan 0, es 86.6%. Es un predictor altísimo, pero no es del 100% (no hace trivial el problema). | **Alternativa**: Eliminar los 0s asumiéndolos errores.<br>**Riesgo**: Eliminar el mejor predictor del comportamiento de deserción (sesgo de supervivencia). |
| **4. Redundancia (Colinealidad)** | Múltiples columnas sobre el 1er semestre (inscritos, evaluados, aprobados). | Mantener, pero aplicar `StandardScaler` en modelos lineales y L2 (Ridge). | Preferimos que modelos regularizados manejen la redundancia. | **Alternativa**: Aplicar PCA.<br>**Riesgo**: Pérdida de interpretabilidad directa (SHAP) en el TF1. |
| **5. Desbalance de Clases y Problema** | `Dropout` es ~32% y `No-Dropout` ~68% en el set de entrenamiento. | Operar como problema **Binario**. Usar métricas como **PR-AUC** y **F1-Macro**. Ajustar hiperparámetro `class_weight='balanced'`. | La clase operativa crítica es "Dropout". Nos interesa priorizar encontrar desertores antes que clasificar perfectamente a los graduados. | **Alternativa**: Accuracy como métrica principal.<br>**Riesgo**: Optimismo engañoso (un modelo tonto que prediga "No-Dropout" sacaría 68% de accuracy). |
