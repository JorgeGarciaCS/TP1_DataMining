# Decisiones de Calidad y Preparación de Datos

Este documento registra las decisiones tomadas en la fase de preparación, cumpliendo con la exigencia de no "inventar" problemas técnicos donde no los hay (el dataset de UCI ya ha sido curado por sus autores), pero sí tratando los aspectos lógicos y de formateo necesarios para el modelado correcto.

| Problema / Ítem | Detección y Evidencia | Decisión | Justificación | Alternativa Descartada / Riesgo |
| :--- | :--- | :--- | :--- | :--- |
| **1. Valores Faltantes** | `train_df.isna().sum()` muestra 0 nulos técnicos en todas las columnas. (Evidencia: EDA) | No aplicar `SimpleImputer` por ahora. | Los autores del dataset reportan "Missing Values: No". Los datos fueron extraídos íntegros de las bases de datos de la universidad. | **Alternativa**: Asumir que "0" significa "Missing". Falso: Un "0" en notas significa que no rindió examen.<br>**Riesgo**: Ninguno directo, pero se añadirá un `SimpleImputer(strategy='median')` en el Pipeline final como buena práctica de ingeniería para tolerar NAs en producción. |
| **2. Categorías codificadas como números** | Variables nominales como `Marital status`, `Nacionality`, `Course` tienen formato numérico (1, 2, 3...). | Aplicar `OneHotEncoder(handle_unknown='ignore')` en el Pipeline para estas variables nominales. | Un algoritmo numérico (ej. Regresión Logística) asumiría que la nacionalidad 105 es "mayor" que la 1, introduciendo un sesgo ordinal falso. | **Alternativa**: Dejarlas como números.<br>**Riesgo**: Falso aprendizaje de relaciones de orden. |
| **3. Valores Extremos (Outliers) en Notas** | El boxplot de `Curricular units 1st sem (grade)` muestra muchos valores de 0 absoluto (outliers visuales). | **Mantenerlos**. No filtrar. | Un 0 no es un error de digitación; es un alumno matriculado que no se presentó a evaluaciones. Es una señal conductual real de abandono inminente. | **Alternativa**: Eliminar filas con nota 0.<br>**Riesgo**: Sesgo de supervivencia (eliminaríamos justo a los alumnos en mayor riesgo que queremos predecir). |
| **4. Redundancia (Colinealidad)** | Múltiples columnas sobre el 1er semestre (inscritos, evaluados, aprobados). Alta correlación obvia. | Mantener las columnas pero aplicar `StandardScaler` a las variables numéricas. | Reducirlas manualmente requiere juicio experto sobre cuál conservar; preferimos que modelos robustos a colinealidad (como Random Forest o Ridge) manejen la redundancia. | **Alternativa**: Aplicar PCA o descartar algunas.<br>**Riesgo**: Pérdida de interpretabilidad directa con SHAP (que es requisito para el TF1). |
| **5. Escala de variables continuas** | Variables como `Admission grade` o `Age at enrollment` están en rangos muy diferentes (0-200 vs 17-60+). | Incluirlas en un `StandardScaler` dentro del `ColumnTransformer`. | Los modelos lineales o de gradiente descender se benefician enormemente en convergencia de la estandarización. Árboles son invariantes a esto, pero usar pipeline unificado sirve para el baseline lineal. | **Alternativa**: No escalar.<br>**Riesgo**: El baseline Logístico fallaría en converger o penalizaría erróneamente coeficientes. |
| **6. Desbalance de Clases** | EDA muestra que `Enrolled` es minoría, y `Graduate` mayoría. | Entrenar modelos con soporte nativo de desbalance (ej. `class_weight='balanced'`) y medir con PR-AUC / F1-Macro. | Accuracy dará falsos buenos resultados (optimismo) prediciendo solo a la clase mayoritaria. | **Alternativa**: SMOTE.<br>**Riesgo**: SMOTE en variables nominales pre-codificadas genera datos sintéticos sin sentido lógico (ej. Nacionalidad 1.5). |
